# Linkex 一括DL— Chrome拡張 / Manifest V3

Linkex の共有リンク（`https://l2e.click/d/…` / `https://www.linkex.io/f/…`）に含まれるファイルを、
フォルダ構成を保ったまま Chrome 標準のダウンロード機能で一括保存します。

> Linkex（LINKINFLU PTE. LTD.）とは無関係の個人開発ツールです。Linkex 側の仕様変更で動かなくなる可能性があります。

## 想定環境
- Windows 10/11 + Google Chrome 116 以降（MV3 / `chrome.scripting` の MAIN world 実行を使用）
- Linkex にログインしていること（Linkex の共有は、ログインしないとダウンロードできない仕組みのため）

## インストール
1. ZIP を展開し、`manifest.json` があるフォルダを任意の場所に置く（削除しない）
2. `chrome://extensions` → 右上「デベロッパーモード」をオン
3. 「パッケージ化されていない拡張機能を読み込む」→ 展開したフォルダを選択

## 使い方
### 共有ページから
1. 共有リンクを開くと右下に「Linkex 一括DL」パネルが出て、一覧を自動で読み込みます
2. 「すべてダウンロード」、または検索で絞り込み／チェックして「選択をDL」
3. 処理用に Linkex ドライブ（`www.linkex.io/drive/all`）が**固定タブで裏に開きます**。処理中は閉じないでください

### ダウンロード済みのスキップ
- 一覧でダウンロード済みのファイルに「DL済み」が付き、「未DLをすべてダウンロード」ではそれらを除いて追加します
- 取り直したいときはパネルの「DL済みも含める」をオンにするか、チェックして「選択をDL」（選んだものはDL済みでも追加）
- 判定は**この拡張の履歴だけ**で行います（共有＋ファイルIDで記録。キューを消しても、保存先の設定を変えても残ります）
- この拡張を入れる前や、ほかの方法でダウンロードしたファイルは「DL済み」になりません
- 手元でファイルを削除すると Chrome が「ファイルなし」と記録するので、取り直しの対象に戻ります
  （Chrome がその記録を更新するのは、ダウンロード一覧を開いたときなどです。すぐに反映されない場合は `chrome://downloads` を一度開いてください）
- Chrome のダウンロード履歴を消した場合も、この拡張の履歴が残っていればDL済みとして扱います
- ポップアップの設定で、スキップのオン／オフと履歴の消去ができます

### URLを貼り付けて
ツールバーのアイコン → 「共有URLから追加」に1行1つずつ貼って「キューに追加」（複数共有を一度に登録可）。

### 保存先
`ダウンロード\<保存先設定>\<共有名>\<共有内フォルダ>\<ファイル名>`（初期値の保存先は `Linkex`）

## 開発者支援（Ko-fi）
| 場所 | 表示 |
|---|---|
| ポップアップ下端 | `☕ 開発者を支援する`（常時） |
| パネル・ポップアップの進行状況 | キューがすべて終わり、1件以上保存できたあとに案内文＋「開発を支援する」 |
| クリック時 | 420×720 の小窓で Ko-fi の支援フォームを開く |

案内文は10パターンで、次の優先順で出し分けます（`config.js` の `MESSAGES`）。
1. 節目（累計 50 / 100 / 500 / 1,000 / 5,000 / 10,000 件を越えた回）
2. 初回
3. 失敗があった回 … 報告だけで、支援のリンクは出しません
4. 一度に50件以上
5. 通常 … 6種を完了回数の順に

支援先を変えるときは `config.js` の `KOFI_USERNAME` だけを書き換えます（`'YOUR_ID'` の間はリンクも案内文も出ません）。

## 処理の流れ（1ファイルごと）
1. 転送量の残りを確認（上限なら一時停止し、リセット時刻に自動再開）
2. 共有から直接ダウンロードURLを発行（`file/get` + `share_token`）
3. 発行できない場合（設定オン時）：
   自分のストレージにコピー → コピー前後のファイルID差分＋同名で**自分のコピーを特定** → URL発行 → **そのコピーだけ**をゴミ箱経由で完全削除
   - コピーは1件ずつ直列実行
   - コピー前から存在したファイルは絶対に削除しません
   - 特定が曖昧（同名の新ファイルが複数）なら推測せず失敗扱い
4. `chrome.downloads` で保存。URL期限切れ（403）などで中断したら、URLを再発行して最大3回再試行

## 設定（ポップアップ → 設定）
| 項目 | 初期値 | 説明 |
|---|---|---|
| 保存先 | `Linkex` | ダウンロードフォルダ配下のサブフォルダ。**次に追加する分から**反映 |
| 同時ダウンロード数 | 3 | 1〜6 |
| 同名ファイル | 番号を付けて保存 | 上書きも選択可 |
| API呼び出し間隔 | 250ms | 速度制限（429）が出る場合は増やす |
| ダウンロード済みをスキップ | オン | 上記「ダウンロード済みのスキップ」 |
| 自分のストレージ経由 | オン | 直接取れないファイルの扱い |
| 転送量の上限で一時停止 | オン | Linkex の転送量APIの値で判定 |
| 追加したらすぐ開始 | オン | |
| 通知 | オン | 完了・ログイン切れ時 |

## 既知の制限・落とし穴
- **Chrome の「ダウンロード前に各ファイルの保存場所を確認する」がオンだと、1件ごとにダイアログが出ます。** `chrome://settings/downloads` でオフにしてください
- ほかのダウンロード管理拡張（IDM連携など）が入っていると、DLを横取りされることがあります。本拡張は自分のDLだけファイル名を固定しますが、横取り自体は防げません
- 途中再開（Range）は Chrome 任せです。期限切れで中断した場合は最初から取り直します
- ストレージ経由の処理中に別タブ・別端末から Linkex のルートへ同名ファイルを追加すると、特定が曖昧になり失敗扱いになります（誤削除はしません）
- 単一ファイルが自分の空き容量を超える場合、ストレージ経由では取得できません（「容量不足」で失敗）
- 一時コピーの削除に失敗した場合は処理ログに出るので、Linkex ドライブで手動削除してください
- 共有ページにパスワードがかかっている場合の動作は未確認です
- ファイル一覧の表示（共有ページのパネル）はログインなしでも動きますが、ダウンロードにはログインが必要です

## 「拡張機能が更新されました」と出るとき
拡張機能を更新・再読み込みすると、開いたままの共有ページは拡張とのつながりが切れます。パネルの「再読み込み」でページを読み込み直してください（ダウンロードの待ち行列は保存されているので、続きから再開します）。

## ほかの拡張機能と競合するとき（ファイル名・フォルダが指定と違う／すぐ失敗する）
症状の例:
```
予定: Linkex/共有名/動画/vlog_day1.mp4
実際: C:\Users\xxx\Downloads\x7f3.bin     （または NETWORK_FAILED で中断）
```
**フォルダだけでなくファイル名まで変わっている**のがポイントです。Chrome 自身はこの書き換えをしません。
ダウンロード管理系の拡張機能が `chrome.downloads.onDeterminingFilename` で名前を上書きしたり、
URL を横取りして自前で取得しようとしたりしている症状です（Linkex のURLは期限付きなので、横取り先での取得も失敗しがちです）。

本拡張は次のように対処しています。
- `onDeterminingFilename` で、自分のダウンロードにだけ保存先とファイル名を主張する。この処理は**自分のダウンロードを出している間だけ**登録し、待機中は外しておく（Chrome は登録している拡張を全ダウンロードの「名前の決定者」に参加させるため、常時登録だと Gofile 一括DL など他の拡張のダウンロードのたびに「別の拡張機能が異なるファイル名を指定しました」という警告が残る）
- 完了時に実際の保存パスを確かめ、名前が違えば警告と通知を出す
- 開始直後に0バイトでキャンセルされたものは「横取りの疑い」として失敗にし、警告を出す
- ポップアップの「保存テスト」で、拡張内ファイルと Linkex の https ファイルを実際に保存して判定する

**対処手順:**
1. `chrome://extensions` で次のような拡張を一時的にオフにする
   - Internet Download Manager（IDM Integration Module）
   - Free Download Manager / 1DM / Turbo Download Manager / Chrono / DownThemAll
   - 「一括ダウンロード」「画像まとめてダウンロード」系の拡張
   - セキュリティソフトが入れたブラウザ拡張
2. 本拡張を **一度削除してから入れ直す**
   Chrome は名前の指定が競合したとき **最後にインストールされた拡張を優先** するため、入れ直すと本拡張が優先されます
3. ポップアップの「保存テスト」を実行し、「判定: 正常です」になることを確認する
   （Linkex のタブを開いた状態で実行すると、https のテストも行います）
4. それでも直らない場合は、ゲストプロファイル（または新しいプロファイル）で本拡張だけを入れて試す

## ファイル構成
| ファイル | 役割 |
|---|---|
| `manifest.json` | 拡張定義 |
| `config.js` | 支援先（Ko-fi）と完了時の案内文 |
| `background.js` | API橋渡し（MAIN world でページの通信モジュールを使用）・キュー・DL管理 |
| `content.js` | 共有ページのパネル（Shadow DOM） |
| `popup.html/.css/.js` | 全体の状況・URL追加・設定・ログ |
